# 接入与边界

## 依赖方向

接入项目持有数据库结构、仓储实现、字段配置、权限规则、设备协议、打印模板和打包参数。框架仅依赖 Python 标准库，以及按需安装的 PyQt5 或 pyserial。接入项目可以单独使用任何一个模块，不要求整体接管应用。

## 状态与异常

表格、导航、表单和管理页面必须在 Qt 事件线程创建和操作。`PageHost.navigate()` 的进入回调失败会尝试回到先前页面；`CrudPage.operation_failed` 把读写失败交给接入项目呈现。`ServiceRegistry` 对依赖排序并在启动失败时停止已启动服务。`BatchPrintRunner` 对一次批处理只保留一个结果，失败后不继续提交后续份数。

## 数据边界

`SqlWhere` 的字段表达式来自接入项目维护的白名单，用户输入只进入 DB-API 参数。`PasswordHasher` 负责密码哈希格式和常量时间比较，账号来源由 `CredentialStore` 提供。`AccessPolicy` 在操作入口调用；更深层的服务接口仍由接入项目验证授权。`SqliteStore` 操作一个 SQLite 文件，备份使用 SQLite 在线备份 API，恢复前完整性检查并留回滚快照；多进程写入协调与业务级一致性由接入项目负责。

## 接入顺序

1. 先接入无界面协议与依赖注入：仓储、授权、通信、打印准备与提交函数。
2. 再声明页面字段、表格列和筛选条件，组合 `CrudPage` 或单独使用控件。
3. 在目标平台验证 GUI 线程切换、打印机和串口，补足业务回归与安装包测试。

## 源流转原则

本仓库以通用接口重新实现机制，不包含原项目账号、患者字段、设备命令、报告模板、数据库内容或资源文件。原项目源码只作为需求证据；后续扩展先判断能力是否跨项目稳定，再把可复用代码和测试放在本仓库。
