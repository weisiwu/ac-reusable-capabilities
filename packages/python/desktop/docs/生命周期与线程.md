# 生命周期与线程

## 所有权表

| 对象 | 创建与调用线程 | 结束方式 | 注意事项 |
| --- | --- | --- | --- |
| BackgroundTaskRunner | Qt 创建、后台执行、Qt 交付 | close，默认等待协作退出 | 父对象销毁会取消；没有强制线程终止 |
| SqliteStore | 同一个拥有者线程 | finally close | 备份前先 commit/rollback；不得拿同一连接给 worker |
| BatchPrintRunner | 应用拥有；start 创建单工作线程 | owner 线程 finally close | prepare/progress 默认 worker；dispatcher 必须同步完成提交 |
| SerialTransport | IO 在锁内串行化 | finally close | 关闭失败保留句柄并报告 TransportError，调用方可重试清理 |
| ServiceRegistry | 应用生命周期线程 | finally stop | reverse cleanup 尝试每个服务；不允许 hook 重入 |
| PageHost | Qt 事件线程 | finally dispose，再 close/deleteLater | hook 自己停止后台任务；失败不跳过其他页 |
| FormDialog/CrudPage | Qt 事件线程 | close/deleteLater | CrudPage 对所有弹窗路径做延迟删除 |
| BusyOverlay/Toast/LiveSearchComboBox | Qt 事件线程 | 随父控件销毁 | 不创建后台查询；计时器由控件拥有 |
| logger handler | 应用确定的写入上下文 | close 并 removeHandler | 不要关闭不属于自己的 handler |
| AuditJournal | 同实例允许多线程追加 | 每次写完关闭文件 | 无跨进程锁；同路径多个实例需应用协调 |
| SingleInstance | Qt 生命周期上下文 | finally release | 保持对象存活，不杀其他实例 |

## 失败处理

Qt 槽不能任由可预期的业务异常逃出。表单校验回调失败通过 validation_failed 报告，管理页面通过 operation_failed 报告。接收信号的应用槽同样应处理自己的异常，不能依赖框架替它清理业务线程。

服务和页面关闭在一个 hook 失败后继续处理剩余对象，最终汇总首个异常。若清理外部资源失败，必须记录未释放项；对象引用清空不等于外部资源已经安全关闭。

## 打印取消与 GUI 派发

取消只在任务边界检查，不强制终止 prepare 或 submit。外部驱动/网络调用必须设置超时。Qt 打印时，worker 的 dispatch_submit 需要同步派发到 GUI 线程并等待结果；GUI 不能一边阻塞等待整个 Future、一边负责处理该派发，否则形成死锁。用事件信号展示进度，在任务结束后由拥有者关闭 runner。

四类无界面资源对象也支持 with：SqliteStore、SerialTransport、ServiceRegistry、BatchPrintRunner。异步查询的连接应在 worker 内单独创建并使用 with，不复用 GUI 线程连接。
