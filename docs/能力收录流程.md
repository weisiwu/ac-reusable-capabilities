# 能力收录流程

## 先判断复用方式

1. 查根目录 [catalog.json](../catalog.json)、包指南、公开标记与测试，比较现有输入输出、依赖和失败行为。
2. 已满足需求时直接接入；可以兼容扩展时补现有能力；确需独立交付、版本周期和领域边界清晰时再创建新包。
3. 将业务实体、schema、硬件协议和部署地址留在接入项目，通过参数、仓储、策略或适配器注入。无法低成本拆开的代码暂不迁入。

## 每次交付的内容

| 内容 | 位置与要求 |
| --- | --- |
| 可独立安装的实现 | `packages/<language>/<domain>`；声明版本、依赖、许可 |
| 版本与环境 | 包内文档；发行名、导入名、包版本、运行时、依赖范围、平台与兼容要求，声明与已验证范围分开 |
| 契约与指南 | 包内 `docs/`；使用流程、属性/类型/默认值、方法、事件、输入输出、异常、线程、资源和副作用 |
| 流程与调用 | 按能力复杂度提供流程图、参数表、最小调用、预期结果和失败清理，不用一串运行命令代替使用说明 |
| 可搜索接口 | 保留稳定 ID 及 [贡献规范](../CONTRIBUTING.md) 的全部公开标记 |
| 独立测试 | 包内 `tests/`；有真实断言，覆盖该能力适用的状态和失败路径 |
| 可运行例子 | 包内 `examples/`；模拟或临时数据，不要求私人设备与账号 |
| 根 demo 入口 | 更新 [demo/catalog.json](../demo/catalog.json)，包 ID 对应根索引，提供运行说明 |
| 场景与导航 | 更新 [能力地图](能力地图.md) 与相关场景，链接权威契约 |
| 来源与验证 | 包内来源许可、实际验证结果、未验证环境与接入责任 |

新增 Markdown 使用现有 YAML 元数据字段。统一文档中心组织选路、组合流程与维护说明，包内文档保留精确用法；Pages 从同一提交渲染为可搜索网页，Markdown 是唯一正文来源。展示页只补功能和体验入口，不堆入接口、版本、依赖、来源或执行命令。新增图使用站点支持的 Mermaid，必要表格和调用示例随正文维护；不另写一套 HTML 文档。没有实现的领域不预建空包，也不按来源项目建立重复目录。

## 验证与审阅

执行 [验证与维护](验证与维护.md) 的入口检查与受影响包验证，检查源代码及文档不含生产数据和私有地址。PR 说明复用评估、接口/兼容变化、demo 命令与实际结果。站点相关变更还要构建文档并走查展示到统一文档中心的链接、目录、搜索、表格、代码复制、流程图和移动布局。合并、发布和接入项目验收分别进行，不能用来源项目测试替代迁入后的测试。

登记前按 [多类型元数据契约](多类型能力与站点接入.md) 补齐来源、能力类型/用途、显式源码与关联示例；安装和运行命令声明自身工具链，不由网站猜测。新语言必须同步原生验证适配与包 CI。

## 贡献导航与文档同步

| 工作 | 规范入口 |
| --- | --- |
| 选择包粒度、稳定 ID、来源与版本 | [目录与收录规则](目录与收录规则.md) |
| 补公开注释、契约、许可与审阅说明 | [贡献规范](../CONTRIBUTING.md) |
| 检查根入口、示例、包测试和 CI | [验证与维护](验证与维护.md) |
| 增加本地 Demo 并声明依赖与 smoke | [Demo 扩展说明](../demo/README.md) |

修改接口时先同步包内契约、例子和测试，再更新 [能力地图](能力地图.md) 与受影响的 [组合场景](组合场景.md)。文档命令应说明工作目录、依赖、预期输出和退出方式；验证结果写明实际执行环境、提交范围与未验证项。旧 Wiki 文件只保留迁移链接，不再新增或复制使用说明。
