# 架构与文档职责

## 组织依据

能力以语言和领域归并，包负责安装、版本和独立验证。来源项目保留可公开的溯源记录，不决定实现路径。现有 Python 桌面包保留 `ctf_desktop` 导入名；完整依赖见 [pyproject.toml](../packages/python/desktop/pyproject.toml)。

| 层 | 内容与职责 | 依赖方向 |
| --- | --- | --- |
| 接入应用 | 业务 schema、权限规则、设备协议、报告模板与部署 | 调用能力包，注入仓储、授权和设备适配 |
| Python desktop 基础 | 查询、CRUD 控制器、授权、SQLite、服务、日志、打印调度 | 标准库；真实串口按需使用 pyserial |
| Qt 组件 | 表格、表单、导航、反馈与后台任务交付 | 基础模块与可选 PyQt5；所有 UI 调用在 Qt 线程 |
| Demo | 用临时数据和模拟外部提交展示组合 | 安装后的包；不向源码目录注入导入路径 |
| 文档与 Wiki | 场景、契约、边界、验证和贡献规则 | 链接包内权威内容，避免复制 API 正文 |

后台任务在工作线程执行 IO，在 Qt 线程交付结果。每个后台操作创建自己的连接和句柄并释放，不能传入 GUI 线程的 SQLite 连接。`latest-wins` 适合查询；每次都必须执行的写入或打印不能直接使用此调度语义。

## 文档更新边界

接口变化时修改包内契约、指南、例子和测试；Wiki 的场景说明只有在选择方式或接入步骤变化时才改。包增删时同步根能力索引、Wiki 能力地图和 demo 清单。历史验证记录保留其环境与提交范围，新提交不能沿用旧提交的结果。

Wiki 源文件在仓库 `wiki/` 下维护，支持本地和 GitHub 仓库浏览；尚未同步到独立的 GitHub Wiki 远端。根 README、Wiki 与文档中心都可以回到相同的包内契约，不另维护一份实现说明。

## 数据与兼容边界

SQLite 能力管理标准明文库，提供迁移与备份恢复，不包含业务数据库版本或加密密钥。打印和通信只提供通用机制；运行 demo 不验证真实硬件。本次组织与入口变更不修改库接口、数据库格式、包版本、加密或发布配置。
