# 架构与文档职责

## 组织依据

能力以语言和领域归并，包负责安装、版本和独立验证。来源项目保留可公开的溯源记录，不决定实现路径。现有 Python 桌面包保留 `ctf_desktop` 导入名；完整依赖见 [pyproject.toml](../packages/python/desktop/pyproject.toml)。

| 层 | 内容与职责 | 依赖方向 |
| --- | --- | --- |
| 接入应用 | 业务 schema、权限规则、设备协议、报告模板与部署 | 调用能力包，注入仓储、授权和设备适配 |
| Python desktop 基础 | 查询、CRUD 控制器、授权、SQLite、服务、日志、打印调度 | 标准库；真实串口按需使用 pyserial |
| Qt 组件 | 表格、表单、导航、反馈与后台任务交付 | 基础模块与可选 PyQt5；所有 UI 调用在 Qt 线程 |
| 功能展示 | 功能入口、效果和浏览器交互；不展开命令、接口或版本依赖 | 公开清单与明确登记的浏览器场景 |
| 本地 Demo | 用临时数据和模拟外部提交展示组合 | 安装后的包；不向源码目录注入导入路径 |
| 文档中心 | 统一的快速开始、能力选择、组合场景、版本兼容、排障及贡献入口 | 根 `docs/` 维护跨包说明，链接包内权威指南与契约 |
| 包内文档 | 精确的依赖、接口、属性、事件、调用和异常清理 | 以包内 Markdown、实现和测试为依据，不在根文档重复维护 API 正文 |
| 文档网页 | 从同一提交的 Markdown 渲染，提供目录、搜索、表格、代码复制和本地 Mermaid 图 | 只负责阅读，不维护第二份正文 |

后台任务在工作线程执行 IO，在 Qt 线程交付结果。每个后台操作创建自己的连接和句柄并释放，不能传入 GUI 线程的 SQLite 连接。`latest-wins` 适合查询；每次都必须执行的写入或打印不能直接使用此调度语义。

## 文档更新边界

接口变化时修改包内契约、指南、例子和测试；文档中心的组合场景只在选择方式或接入步骤变化时更新。包增删时同步根能力索引、[能力地图](能力地图.md)和 demo 清单。历史验证记录保留其环境与提交范围，新提交不能沿用旧提交的结果。

文档中心正文维护在根 `docs/`，精确能力说明继续在包内 `docs/` 维护。Markdown 是唯一正文权威；Pages 从同一次 checkout 生成 `docs/README.html` 及相关文档网页，相对 Markdown 链接改写为同站链接，源码入口固定到同一次构建提交。旧 `wiki/` 文件仅保留迁移说明，旧网页地址跳转至对应的文档中心页面，不再维护并列内容或独立 Wiki 入口。

包文档需说明适用版本、运行环境、必要和可选依赖、兼容变化及已验证范围；组件补齐属性、默认值、信号和生命周期，流程补齐前置条件、失败恢复、幂等和资源释放。文档中心的上手与组合场景引用这些内容，不复制整份 API 正文。页面搜索、复制和 Mermaid 图由站点本地资源提供，构建维护见 [站点说明](../site/README.md)。

## 数据与兼容边界

SQLite 能力管理标准明文库，提供迁移与备份恢复，不包含业务数据库版本或加密密钥。打印和通信只提供通用机制；运行 demo 不验证真实硬件。本次展示和文档变更不修改能力包接口、数据库格式、包版本或加密方案。站点增加文档渲染依赖，发布仍遵循 PR 构建、经授权合并后由 `main` 部署。
