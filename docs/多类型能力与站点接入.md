# 多类型能力与站点接入

## 设计检查与调整

原站点能展示当前桌面包，但默认打开 Qt 对应交互、按 Python 布局推导 `.py` 源码路径、用 pip 拼接安装命令，无法直接承接不同技术栈。多类型调整将首页改为通用能力目录；当前再按展示与接入分层：展示页提供功能效果和交互，示例命令与接入细节集中到[文档中心](README.md)。

当前只有一个实际收录包，15 项能力各有一个明确登记的浏览器 mock；功能展示与文档中心共用 `docs.css` 和相同页面骨架。不为显示多样性建立空包、虚构来源或能力数量。筛选选项从真实登记内容生成；未来新增内容按语言、领域、类型、来源与体验方式检索，并按页展示。

## 四类实体及其关系

| 实体 | 管理内容 | 关系 |
| --- | --- | --- |
| 来源 origin | 稳定来源 ID、可公开名称、来源与许可记录 | 一个来源贡献多个能力；同一能力也可关联多个来源 |
| 能力包 package | 语言、领域、独立版本、许可、README | 按交付边界归并能力，不按来源项目复制代码 |
| 能力 capability | 稳定 ID、用途、类型、标签、源码、指南和契约 | 归属一个包；跨项目复用不改变身份 |
| 演示 demo / scene | 本地或文档示例、可选浏览器场景 | 一个示例可覆盖多个能力；能力不强制拥有浏览器实现 |

来源名称可采用审阅后的公开别名，私有仓库地址、业务实体、生产数据和个人知识库路径不进入网站。`package.origin_ids` 是默认来源，能力自己的 `origin_ids` 可覆盖，适合后续多来源合并。

## 能力登记

根目录 `catalog.json` 继续使用 schema_version 1，新增元数据兼容已有字段；以下字段由网站实际消费，不靠目录名推断行为：

| 字段 | 含义 |
| --- | --- |
| package.language / domain / version / license | 技术栈、能力领域、版本及包许可；语言与领域分别筛选 |
| capability.kind | 职责类型：component 组件、library 基础库、workflow 流程、adapter 适配器、tool 工程工具；新类型保留原值显示 |
| capability.summary / tags | 一句具体用途与检索标签，不复述营销描述 |
| capability.sources | 明确的仓库相对源码文件列表，可为 `.py`、`.ts`、`.go`、脚本或其他格式；站点不拼扩展名 |
| capability.guide / contract | 接入说明与权威契约，须为真实存在的文档 |
| capability.demo_ids | 可选的示例关联，允许为空 |
| capability.origin_ids | 可选的来源关联，缺省继承所在包 |

稳定能力 ID 不因移动文件或来源项目更名而变更。用途相同的能力先评估兼容扩展；不为每个来源项目再造一份相同能力。

## 按能力选择演示方式

- 浏览器演示：适合 Web 原生组件或可明确说明边界的交互示意。`site/demos.json` 关联 renderer、能力 ID、可选本地示例 ID，以及分组、标题和简短场景摘要；当前 15 个 renderer 为 `table`、`form`、`filters`、`feedback`、`navigation`、`crud`、`query`、`search`、`storage`、`printing`、`auth`、`transport`、`services`、`runtime`、`redact`。每项初始样例、结果和模拟边界见 [站点场景表](../site/README.md#当前场景与边界)。新增 renderer 需要实现、浏览器验证与测试，不因登记条目自动执行任意代码。
- 本地示例：适合桌面、服务端、CLI、设备和环境相关能力。在 `demo/catalog.json` 明确 `mode: local`、`runtime`、`command`、`install`、可选 `smoke_command` 及真实脚本/指南路径。文档和本地启动器使用清单中的真实命令，不添加 pip、Qt 或某种后缀；功能展示页只提供场景与文档入口，不展开命令。
- 文档接入：适合数据契约、协议说明或暂不提供独立可执行例子的能力。能力可仅通过指南与契约进入站点；如需登记文档示例，使用 `mode: documentation`，可以没有脚本和运行命令。

三种方式不是互斥的，目录可按任一可用方式筛选。浏览器示意不证明后端、设备、升级路径或目标平台行为。功能展示页保留用途、效果、体验方式及文档入口；真实来源、版本、依赖、兼容要求、许可、源码和运行示例由文档中心与包内文档承接。

`demo/run.py` 仍只直接执行 Python；它可以发现和检查其他运行时或文档条目，执行时显示登记命令或说明，不把非 Python 文件交给 Python，也不自动执行清单中的 shell 字符串。其他运行时由对应工具链运行。

## 浏览器场景接入约束

| 项目 | 要求 |
| --- | --- |
| 显式登记 | 构建器校验已实现 renderer 的名称、唯一性、能力 ID 和可选示例 ID；`scene-registry.mjs` 注册对应函数，不根据语言或元数据自动生成演示 |
| 初始状态 | 一进入即可看见有意义的数据、预填输入和结果；不能只显示空状态、脚本命令或操作说明 |
| 行为范围 | 仅模拟功能可见效果；权限、口令、设备、数据库和系统行为不得冒充真实认证、驱动、迁移或单实例机制 |
| 状态与重置 | 顶部可重置当前场景；离开后返回重新创建样例，不持久化，也不把一个场景的编辑隐式同步到其他场景 |
| 资源清理 | renderer 返回清理函数；切换、重置和离开前清除计时器及待交付查询，旧操作不得写入后续场景 |
| 实现依赖 | 当前仅使用本地 ES module、DOM 和有限计时器，不需 npm 安装，不发外部业务请求，不访问真实设备或数据库 |
| 新包选择 | 可以只提供文档或本地例子；未来新语言与新能力不因进入目录就自动获得浏览器 mock，也不强制补造一个演示 |

浏览器 mock 和真实能力实现分别验证。即使场景完整，也不能用其结果替代 Python / Qt 的契约、资源释放、目标设备或业务升级验证。


## 验证边界

以下临时跨语言条目验证属于早期多类型目录版本，保留其验证范围，不作为当前改版已验证的证明。网站构建器可以处理跨语言路径与命令。测试用临时 TypeScript/Shell 两个领域、Node 运行示例和纯文档能力验证展示结构，不将它们加入真实目录；没有浏览器场景时实验室自动隐藏。

这不等于所有语言的代码验证已实现。根代码契约检查器仍为 Python 提供 AST 和清单适配；新语言首次迁入时必须增加对应清单适配、原生测试及包 CI，不能删除拒绝规则后把未验证代码视为通过。站点元数据兼容与原生代码验收分别记录。

新增内容顺序：复用评估 → 独立包及原生验证 → 权威契约/来源 → 真实能力和示例登记 → 文档中心导航 → 可选浏览器场景 → 网站构建与交互检查 → PR 审阅。包的来源许可、版本变化和适用范围由自身维护，网站只帮助发现与接入。
