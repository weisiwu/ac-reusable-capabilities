# GitHub Pages Demo 站点

站点入口：<https://weisiwu.github.io/ac-reusable-capabilities/>。展示内容由本目录静态页面与仓库真实能力清单构建，文档中心从同一次 checkout 的 Markdown 渲染；是否完成某次发布，以 GitHub Actions 的部署状态及线上版本为准。

## 当前场景与边界

`site/demos.json` 当前为根能力目录的 15 项能力各登记一个浏览器 mock。每项进入后已有样例数据和可见结果，不要求先阅读脚本或提交空表单。下表记录当前 renderer 的初始状态与实际模拟范围，不是 Python 契约测试结果。

| renderer / 场景 | 初始样例和结果 | 可操作范围与边界 |
| --- | --- | --- |
| `table` 数据表格 | 24 条资料，每页 6 条，已显示首条详情 | 搜索、分类、翻页和查看；只处理页面内数组 |
| `form` 表单与详情 | 1 份预填资料、实时预览和成功状态 | 编辑、校验、保存和恢复；保存仅更新当前场景，不写回其他场景 |
| `filters` 筛选与联想 | 预选分类的 8 条结果、已填负责人和联想候选 | 关键词、分类、状态组合筛选与候选选择；不发远端联想请求 |
| `feedback` 操作反馈 | 3 条样例与已加载提示 | 成功、失败、有限加载和确认/取消；只改变页面提示与样例状态 |
| `navigation` 页面导航 | 概览、6 项任务（2 已完成）、4 条历史 | 概览/任务/历史切换与标记完成；场景内共享状态，不是应用路由或 Qt 页面生命周期 |
| `crud` 资料管理 | 24 条资料，首条已选中并填入编辑器 | 新增、编辑、删除和字段校验；没有仓储、事务或服务端权限执行 |
| `query` 条件查询 | 全部 24 条记录，最低金额 0，每页 6 条 | 修改条件、分页和恢复预设；过滤页面数组，不构造或执行 SQL |
| `search` 后台搜索 | 关键词「能力」、当前能力结果（现为 15 项，首屏列出 8 项） | 防抖、最新结果、取消和超时；等待/失败保留旧结果，用有限计时器模拟慢查询 |
| `storage` 备份与恢复 | 24 条数据、20 条和 18 条的 2 个快照 | 新增、快照、恢复和升级状态模拟；不打开 SQLite、不执行真实迁移 |
| `printing` 批量打印 | 4 项报告队列、1 项已完成，共 6 份 | 批量处理、取消和重置；只推进队列状态，不调用打印对话框或打印机 |
| `auth` 权限与校验 | 3 种角色、5 项操作对照、已匹配的样例口令 | 切换角色、尝试编辑和口令匹配；不执行 PBKDF2、真实认证或服务端授权 |
| `transport` 设备通信 | 已连接的终端、3 条收发记录 | 发送、断连/重连和超时；不使用 WebSerial，不访问设备端口 |
| `services` 服务管理 | 4 项运行中服务和启动日志 | 按序启动、反序停止和失败回滚；不创建系统服务、子进程或后台线程 |
| `runtime` 配置与单实例 | 3 个样例目录、有效 JSON 和 4 项检查结果 | 修改配置、检查和第二实例拦截；目录仅为文本，不创建文件或系统单实例锁 |
| `redact` 日志与脱敏 | 嵌套 JSON、6 个敏感键的脱敏对照和 1 条审计记录 | 重处理、错误 JSON 和恢复；错误时保留有效输出，只识别结构化敏感键，不识别任意自由文本隐私 |

所有记录和身份均为虚构数据；设备、数据库、服务、权限与系统行为全部在浏览器中模拟。没有外部业务请求、真实文件或设备操作、上传、持久化及统计服务。静态页面仍需从站点加载自身资源。真实 Python / Qt 的参数、线程、迁移、授权和失败清理契约，独立维护在包内源码、指南与测试中。

## 样例重置与生命周期

每项场景均可使用顶部「重置样例」恢复默认数据。切换到其他场景再返回、或刷新页面，也会重新创建样例；不同场景之间不共享编辑结果。导航演示内部的概览/任务/历史会保留本次场景状态，离开该场景后重建。

切换或重置前先调用当前 renderer 返回的清理函数，再建立新场景。等待、加载、打印和搜索使用的计时器均应结束或清除，未完成的旧搜索不得更新新场景。`scene-registry.mjs` 汇集明确实现的 renderer，`demo-kit.mjs` 提供 DOM 与生命周期工具，`mock-data.mjs` 每次返回一份新的虚构资料；它们都是纯 ES module，无 npm 安装步骤。

## 展示与文档分层

展示页和文档中心共用 `docs.css` 的设计系统：字体、颜色、页头、导航和控件一致。页面结构按任务安排，避免把演示、目录与文档堆成一条长页：

- 首页是紧凑的分组能力索引，支持搜索、分组以及语言、领域、类型、体验方式筛选；不自动打开演示。
- `#demo/<renderer>` 是单项体验视图，仅呈现当前演示、重置与使用文档入口；下方不追加能力总览或组合场景。
- `#recipes` 单独呈现组合场景；文档中心采用正文阅读列与章节目录。
- Demo 与文档侧边栏共用手风琴：默认展开当前页面所在组，展开另一组时收起前一组，也可全部收起；分组标题支持键盘操作。手机外层导航仍可展开和收起，表格在自身区域横向滚动。
- 目录到演示使用浏览器历史，前进、后退恢复对应视图；返回目录保留搜索与筛选。离开演示即释放任务，页面从浏览器缓存恢复时重建默认样例。

保留 `#overview`、`#examples`、`#lab` 和 `#docs` 的旧入口；无效场景或分组入口返回有提示的目录。视觉设计依照用户指定的 [Impeccable](https://github.com/pbakaus/impeccable) 方法，产品约定见根 `PRODUCT.md`，设计系统见 `DESIGN.md`。这两份开发资料不进入文档发布目录。

| 入口 | 内容 | 正文来源 |
| --- | --- | --- |
| 能力目录与独立交互 Demo | 先选择能力，再进入功能操作；保留简短模拟标注 | `site/index.html`、`site/assets/` 与公开清单 |
| `docs/README.html` | 统一的快速开始、能力地图、组合场景、版本兼容、排障与贡献导航 | 根 `docs/` 中的 Markdown |
| 包内文档网页 | 精确依赖、兼容、流程、属性、信号、调用及异常清理 | 已收录包内的权威 Markdown |

旧 `wiki/Home.html`、`wiki/Getting-Started.html` 等地址保留迁移跳转，分别进入文档中心对应页面；`wiki/` 中的 Markdown 仅作为迁移存根，不作为新导航入口，也不重复参与内容搜索。

文档中心提供页面目录、搜索、表格、代码复制和流程图。Markdown 是唯一正文来源；网页链接在构建时改写为同站 HTML，源码入口固定到构建提交，不另手工维护 HTML 正文。Mermaid 11.12.1 随站点资源本地提供，浏览器无需访问 CDN。

## 本地构建与预览

在仓库根目录使用 Python >= 3.11；先安装固定的站点构建依赖 `Markdown==3.8.2`。无需安装 Qt。

```bash
python -m pip install -r site/requirements.txt
python site/build.py
python -m http.server 8000 --bind 127.0.0.1 --directory dist/pages
```

打开 `http://127.0.0.1:8000/`，结束后停止预览服务。不要直接打开 HTML 文件：站点使用浏览器模块加载。所有静态资源使用相对路径，兼容 GitHub 项目站点的仓库路径前缀。

`--output` 可指定构建目录，默认 `dist/pages`；`--repository owner/name` 支持同结构 fork。`--ref` 指定源码链接版本，CI 使用 `GITHUB_SHA`，使指南与源码指向同一发布提交。本地默认 `main`。文档构建范围由公开入口、已收录包与其文档组成；仅输出受控正文、静态资源和公开清单派生数据，不复制任意工作区文件。

## 发布

[Pages 工作流](../.github/workflows/pages.yml) 在 PR 上执行构建与测试，在 `main` 推送后构建并发布；也支持从 `main` 手动触发。仓库 Pages 的 Build and deployment 使用 GitHub Actions。部署权限仅授予 deploy job，PR 不发布站点。合并必须获得维护者授权。统一文档中心已在 [PR #7](https://github.com/weisiwu/ac-reusable-capabilities/pull/7) 合并至 `e68c2bc` 并发布；后续改版分别核验自己的发布记录与线上提交，不能沿用旧发布结果或以本地构建代替线上更新完成。

发布使用 `configure-pages`、`upload-pages-artifact` 与 `deploy-pages`，配置依据 [GitHub 官方文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。开启服务不等于发布成功，需核对 deploy job、站点可访问性和页脚提交号。回滚时对默认分支执行经审阅的还原提交并重新部署，不手改站点成功状态。

## 维护与验证

```bash
python scripts/check_catalog.py
python scripts/check_docs.py
python demo/run.py --check
python -m unittest discover -s tests -v
node --test site/tests/*.test.mjs
node --check site/assets/app.mjs
node --check site/assets/docs.js
python site/build.py
```

Node >= 22 用于内置测试工具与语法检查；日常站点构建不需要 npm 安装。Mermaid 的本地分发文件、版本和许可应一并维护。`catalog.json` 与 `demo/catalog.json` 是真实内容来源；新增 Python 包会自动进入索引。源码文件、运行时与命令由清单显式声明，构建器不再按 Python 布局推导。多类型接入见 [元数据与站点设计](../docs/多类型能力与站点接入.md)。新语言仍需补原生代码验证适配与 CI。浏览器交互是显式选择的场景，不因新增清单项自动生成交互实现。
